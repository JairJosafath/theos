## 1. A ready issue without a checklist: the needs-human comment shows an example
$ gitea issue apps/hello#7 body:
hello should accept a name and greet it.
$ labels: ["status/needs-human"]
$ comment:
This issue has no "Acceptance criteria" section with a checklist ("- [ ] ..."), so a reviewer could not tell when it is done. Add one, then label it status/ready again. For example:

```markdown
## Acceptance criteria

- [ ] An empty order is rejected with a message naming the missing field
- [ ] A test covers the empty order
```

Each item is one check a reviewer can verify in the pull request.
