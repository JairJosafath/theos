Next:
1. Commit this as .theos.yaml on the repository's main (or run again with --write-identity):

     project: factory
     softwareSystem: factory
     container: theos
     type: service
     scaffoldedFrom: []

2. Have the repository in the organization GitProvider git names, as theos.
3. Read the model above, change what is wrong, and apply it: kubectl apply -f model.yaml
4. kubectl -n factory get container theos -o jsonpath='{.status.conditions[?(@.type=="Protected")].message}'
   says whether main reports the checks the model names, or which it reports instead. When it reports
   none, the repository's workflows don't run on this Git host: each job's runs-on must be a label of
   the project's CI runners, which GitProvider git lists in its spec.ci.
