C4 Factory · v2 · the agent factory · 1 October 2026

Agents build the apps.
The platform keeps them in their workspace.

A Task gives an agent a goal for one Container. The operator runs it in a sandbox, lets CI and a second agent judge the result, and merges only what passes both. Proven on offline tool apps: no ads, no subscriptions, no logins.

The loop

One Task, from goal to merge

TaskGoal for a Container, an Agent from the catalog. Immutable spec.
→
ImplementAgent Sandbox pod runs c4agent: clone, Claude Code, make check, push branch.
→
Pull requestOperator opens it in Gitea. main is protected.
→
CIGitea Actions runs the Standard's check on the slim Flutter runner.
→
ReviewA fresh agent reads the diff against AGENTS.md: approve or changes.
→
MergeSquash, review posted as a comment, agent credited as co-author.

↺ CI failure or "changes" starts the next round, with the review or the failing CI log as feedback (max 3 rounds by default).

New kinds

Three kinds, still one operator

StandardCatalog layer after the Framework: lint rules, style guides, Makefile, CI. Distilled from Google, LLVM, Chromium, Mozilla, kernel, Core Guidelines, Rust naming, GNU.
AgentCatalog entry: image, credentials Secret, max rounds, timeout, resources. Claude Code or a stand-in.
TaskPending → Implementing → Checking → Reviewing → Merged / Failed. Rules in model.NextTaskStep.

New Container type mobile-app; the operator never branches on a type, so AWS serverless is another catalog, not new code.

The fence

What an agent can't do

  • No Kubernetes credentials: no ServiceAccount token; results go out as the pod's termination message.
  • Git as a restricted bot user, write access to its own repository only.
  • No pushes to main: merge needs green check* and an approving review.
  • Can't touch .devcontainer/, .gitea/ or .c4factory.yaml.
  • NetworkPolicy: DNS, Gitea and public HTTPS only.
  • A deadline on every run, one sandbox at a time, fair queue for the slot.
