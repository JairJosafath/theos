# The operator as a Helm chart

**Goal:** A device installs c4factory with `helm install`: the operator, its CRDs,
RBAC, the admission policy and the UI, with values for the images and the Git
provider. Issue #98; spec in [user-issues.md](user-issues.md), *Not in this plan*.

**Why:** Devices build their products with c4factory as a Helm release, but the
operator installs only through kustomize into the Kind test cluster.

## Shape

- The chart lives in `dist/chart/`, generated by kubebuilder's `helm/v2-alpha`
  plugin from `make build-installer`'s `dist/install.yaml`; `make chart`
  regenerates it. Templates from the kustomize output regenerate on every run, so
  hand-written parts live in files the plugin does not generate:
  `templates/ui/` and `templates/gitprovider/`, and `values.yaml`, which the
  plugin keeps without `--force`.
- **Images:** `manager.image` and `ui.image` (repository, tag, pullPolicy).
- **UI:** `ui.enabled` (default true) installs the read-only UI in the release
  namespace, with the same read-only ClusterRoles as `config/ui/`.
- **Git provider:** `gitProviders`, a list of `{namespace, name, provider, url,
  owner}` plus a token or an existing Secret. Each becomes a GitProvider (and its
  credentials Secret) in that namespace. CRDs are chart templates, so these are
  `post-install,post-upgrade` hooks: Helm builds hooks only after the release's
  CRDs exist. The namespace must exist.
- **Prerequisite:** Agent Sandbox (the Task controller owns its `Sandbox`
  kind), installed from its release manifest; the chart's NOTES and README say so.
- The Kind test environment keeps kustomize (`make deploy`); the README's
  install path stays the Kind one until images and the chart are published (the
  follow-up issue for a release workflow).

## Steps

1. `config/policy`: the binding gets its own name; the plugin writes one file
   per name, so the policy and its binding shared one and the policy was lost.
2. `kubebuilder edit --plugins=helm/v2-alpha`; `.gitignore` keeps `dist/chart/`;
   `make chart` target.
3. `templates/ui/`, `templates/gitprovider/`, values and NOTES.
4. `.github/workflows/test-chart.yml`: `helm lint`, then install into a Kind
   cluster with Agent Sandbox and the operator image, with a GitProvider value,
   and check the release, the manager's rollout and the GitProvider.
5. Docs: `docs/dev/structure.md`, `docs/dev/testenv.md`, chart README.

## Done when

- `helm lint dist/chart` passes and `helm template` renders the operator, CRDs,
  RBAC, policy and binding, UI and a GitProvider from values.
- The *Test Chart* workflow installs the chart into a fresh Kind cluster and the
  manager and UI become ready, on the pull request.
- `make check` passes.
