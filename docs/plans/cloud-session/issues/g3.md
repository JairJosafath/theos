## Context

Third step of `docs/plans/cel-lens-everything-one-step-away.md` (JairJosafath/cel-lens#3). The request: "Right-clicking in YAML with CEL gives a cel-lens submenu with what applies there, and nothing in files where cel-lens does nothing", and everything is in the Command Palette.

The extension contributes no `editor/context` menu and no `submenus`. It holds the engine's list of every file with rules and their spans (`src/rule_list.ts`, from `cel-lens.ruleList`), and `ruleAtCursor` (`src/rule_at_cursor.ts`) finds the rule at a position. Twelve commands are hidden from the palette, among them the view's filter and following commands, which take no argument.

## Goal

In a YAML file the engine lists rules for, right-click (or the editor title's overflow menu) gives a *cel-lens* submenu with the rule's actions when the cursor is in a rule, the toggles and the two settings; in any other file there is none. Every command that needs no argument is in the palette.

## Acceptance criteria

- [ ] `contributes.submenus` has `cel-lens.editor`, label *cel-lens*. `menus.editor/context` shows it in group `1_cel-lens` and `menus.editor/title` in a group that is not `navigation` (the overflow, no icon), both with `when` `editorLangId == yaml && cel-lens.editorHasRules`.
- [ ] `menus.cel-lens.editor` holds, by group:
  - `1_rule`: `cel-lens.showRule` (retitled *Show Problems*) and `cel-lens.rules.reveal` when `cel-lens.ruleAtCursor`; `cel-lens.showExampleResults` when `cel-lens.ruleAtCursor == ruleWithExamples`; `cel-lens.giveValueType` when `cel-lens.cellensTypes`;
  - `2_toggles`: *Toggle Colors*, *Toggle Inline Info*, *Toggle Example Results*, and *Toggle Value Types* when `cel-lens.cellensTypes`;
  - `3_settings`: *Pick Kubernetes Version*, *Choose Color Style*.

  `src/manifest.test.ts` holds each entry, group and `when`, and that *Show Logs* and *Restart Engine* are not in it.
- [ ] `cel-lens.editorHasRules` is true when the active editor's file is in the engine's list (compared in the editor's spelling of the URI, as following the editor does), and false otherwise, with no editor, or with no list (the engine down or unable to list). It is set when the active editor changes and after each answer, only when its value changes. Tests: a file with rules, a YAML file without (a GitHub workflow), a file under *Open files*, an answer that removes the file, a restarted engine.
- [ ] `cel-lens.ruleAtCursor` is `ruleWithExamples` when the cursor is in a rule whose row shows example words, `rule` for another rule, and unset outside a rule or a file with rules; set on each selection change of the active editor and each answer, only when it changes, with no delay. The lookup is in a module without `vscode`, with tests: on the rule's key, inside a block scalar, between two rules, in a document of several, with example results off for the folder.
- [ ] Run from the submenu (an argument that is a URI, or none), `cel-lens.showRule` and `cel-lens.showExampleResults` look up the rule at the cursor again and act on its location; run from the line or the view (a location), they act as today. With no rule at the cursor they show `cel-lens: the cursor is in no rule` in the status bar for 3 seconds (`window.setStatusBarMessage`) and do nothing else. Tests for each.
- [ ] `cel-lens.rules.reveal` (*Reveal in Rule View*) reveals the rule at the cursor in the view, else its document, with `select: true, focus: true, expand: true`, opening the view; a rule the filter hides reveals its document. In the palette with `editorLangId == yaml && cel-lens.editorHasRules`. Tests against `test/vscode.ts`.
- [ ] In the palette: *Show Problems Only* with `!cel-lens.ruleView.problemsOnly`, *Show All Rules* with `cel-lens.ruleView.problemsOnly`, *Follow Editor* with `!cel-lens.ruleView.followEditor`, *Stop Following* with `cel-lens.ruleView.followEditor`; run from the palette, the two filter commands also open the view (`cel-lens.rules.focus`). The commands that need a rule or a row as argument stay hidden. `INTERNAL_COMMANDS` in `src/manifest.test.ts` follows, and `TITLE_VERBS` gains *Reveal*.
- [ ] A bench in `src/rule_list.bench.ts`: the key update after a selection change in a file of 500 rules within a list of 5,000, median within 1 ms.
- [ ] `CHANGELOG.md` has the entry under *Unreleased*; the README is step 7's.

## Out of scope

The shortcut (step 4), the walkthrough's *Get Started* (step 5), the README (step 7). A context key or notification from the engine: the plan's decision 5 says why the list it already sends is enough.

## Notes

- A key that lags a fast right-click shows the previous state for a moment; the commands look up again when run, so they never act on the wrong rule.
- A file just opened gets the submenu once the engine's list has it, within a second; say so in the CHANGELOG entry only if a person would notice.
