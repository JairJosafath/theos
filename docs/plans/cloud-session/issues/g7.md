## Context

Seventh step of `docs/plans/cel-lens-everything-one-step-away.md` (JairJosafath/cel-lens#3). The request: "The README lists every command with its shortcut, and every setting, in the order a person meets them."

The README's sections are fixed by `src/readme.test.ts` (*What it looks like*, *Install*, *Give a value a type*, *Example results*, *Rule view*, *Commands*, *Settings*, …). Its *Commands* table has no shortcut column and lists nine commands in no order a person meets; its *Settings* table has `ruleView.followEditor` fourth, while the settings' `order` in `package.json` puts it last. Steps 1 to 5 added *Toggle Colors*, *Toggle Value Types*, `cel-lens.valueTypes`, the status bar menu's order, the editor's submenu, *Reveal in Rule View*, the view's commands in the palette, `Ctrl+K L` and the walkthrough with *Get Started*. The plan's decision 9 sets one order: the walkthrough's, then the menu's.

## Goal

A person reading the README meets cel-lens in the order they meet it in VS Code, finds where everything is and how to turn off each thing it draws, and sees every command with its shortcut and every setting, in that order, which the Settings editor shares.

## Acceptance criteria

- [ ] The sections, in `src/readme.test.ts`: *What it looks like*, *Install*, *Get started*, *Where to find it*, *Give a value a type*, *Example results*, *Rule view*, *Commands*, *Settings*, *Supported Kubernetes versions*, *Experimental features*, *Not supported yet*, *License*, *Contributing*.
- [ ] *Get started* says, in a few sentences, that the Welcome page has *Get started with cel-lens* (its four steps by name), that **cel-lens: Get Started** opens it, that cel-lens opens nothing by itself, and that VS Code's `workbench.welcomePage.walkthroughs.openOnInstall` decides whether VS Code shows it after an install.
- [ ] *Where to find it* has: the status bar menu, with `images/actions-menu.png` and its alt text, and its entries in order; the editor's *cel-lens* submenu, with `images/editor-menu.png` and its alt text, and when it shows (YAML files with rules the engine checks) and its groups; the palette; the shortcut `Ctrl+K L` / `Cmd+K L` with the note on Vim's `vim.handleKeys`; and a table *Turn it off* with one row per thing drawn (colors, the line, example results, value types): its toggle command, its setting and its menu entry, and that each takes effect at once.
- [ ] *Commands* has the columns *Command*, *Shortcut*, *What it does*, and its rows in the order of the plan's decision 9, every palette command once, `none` where there is no shortcut; one sentence under it says how to bind any of them in **Preferences: Open Keyboard Shortcuts**. A test reads the rows' order from an exported list shared with the status bar menu's (step 2) and the keybindings of `package.json` for the *Shortcut* column.
- [ ] *Settings* lists every setting in the order of decision 9 (`kubernetesVersion`, `colorStyle`, `inlineInfo`, `exampleResults`, `valueTypes`, `ruleView.followEditor`, `experimental`, `trace.server`, `serverPath`), and `package.json` gives them `order` 0 to 8 in that order. `src/manifest.test.ts`'s order test and `src/readme.test.ts` hold both against one list.
- [ ] `test/pictures/take.ts` takes `images/actions-menu.png` (the status bar menu open over a CRD) and `images/editor-menu.png` (the submenu open at a rule), in the README's viewport and theme, reusing its helpers and adding no guard; the session takes them if the sandbox cannot, and says so in the pull request.
- [ ] *What it looks like* links to *Get started* and *Where to find it*. The other README tests (`readme.test.ts`, `docs_wording.test.ts`, `check_links.test.ts`) pass; `npm run links` passes.
- [ ] `CHANGELOG.md` has the entry under *Unreleased*.
