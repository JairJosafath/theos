## Context

Sixth step of `docs/plans/cel-lens-everything-one-step-away.md` (JairJosafath/cel-lens#3). The request: "Everything reads well in light, dark and high-contrast themes, and nothing relies on colour alone."

`src/cel_styles.test.ts` holds every colour of both styles to 4.5:1 against `#FFFFFF` and `#1E1E1E` (Dark+) and 7:1 against `#000000` and `#FFFFFF` for high contrast; Default Dark Modern, VS Code's default dark theme, has `#1F1F1F`. The rule view's rows set `accessibilityInformation` (`ruleAccessibleLabel`); the status bar item sets none. `npm run pictures` (`test/pictures/take.ts`) takes every picture in Default Dark Modern only. The agents' sandbox lacks Chromium's system libraries, so the session takes pictures (`docs/project-notes.md`). Steps 1 to 5 added the toggles, the menu, the editor's submenu and the walkthrough.

## Goal

Each element says what it says in words or shapes as well as colour, held by tests where a test can see it, and a set of pictures in the four default themes shows the rest.

## Acceptance criteria

- [ ] `src/cel_styles.test.ts` adds Default Dark Modern's `#1F1F1F` (4.5:1) beside Dark+'s `#1E1E1E`, with the theme each background is from in the table. Any colour that fails is changed in `src/cel_styles.ts` with its reason in the commit.
- [ ] The rule view: a test that the four icon states (`error`, `warning`, `pass`, `check`) have four different product icon ids, and that each state's row description and `accessibilityInformation` say it in words (`N problems`, the example words, `compiles`, and `error,` or `warning,` where the icon is the only other sign).
- [ ] The status bar item sets `accessibilityInformation`: `cel-lens, Kubernetes 1.36, click for actions` while running, `cel-lens engine down, click to restart it or show the logs` when failed or crashed. Tests for both.
- [ ] A test that no colour carries a state on its own: the line's lenses have no colour of their own (titles only), the menu's toggle values are words, and the walkthrough SVGs use theme variables only (step 5's test, named here).
- [ ] `npm run pictures -- themes` takes, in Default Light Modern, Default Dark Modern, Default High Contrast and Default High Contrast Light, six scenes: a CRD with its colours and lines (`widget_crd.yaml`), a problem with its hover, the rule view with a rule in each state, the status bar menu, the editor's *cel-lens* submenu, and the walkthrough's first step; it writes `out/pictures/themes/<scene>-<theme>.png`, never `images/`, reusing the script's helpers and adding no new guard (`docs/project-notes.md`). `src/picture_script.test.ts` still passes.
- [ ] The session takes the set (with `CEL_LENS_CHROME` if the sandbox cannot), looks at each picture against this list, and records the result in the pull request: every CEL part readable on its background; the line readable and distinct from the YAML; the squiggle and hover visible; each rule state told apart by its icon's shape and its words; the menu's values readable; the submenu's entries readable; the walkthrough's picture readable, its outlines visible in high contrast. Each failure is fixed in this step or filed, with the picture.
- [ ] The set is copied to theos `docs/screenshots/cel-lens-everything-one-step-away/` by the session as the plan's evidence; it is not committed to cel-lens.
- [ ] `CHANGELOG.md` has an entry under *Unreleased* only for what a person sees change (a colour, the status bar item's accessible name).

## Out of scope

Retaking the README's pictures in other themes (they show features, not themes); contributing theme colours for the parts (`contributes.colors`); the README (step 7).
