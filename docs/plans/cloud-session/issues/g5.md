## Context

Fifth step of `docs/plans/cel-lens-everything-one-step-away.md` (JairJosafath/cel-lens#3). The request: "A short *Get started with cel-lens* walkthrough on VS Code's Welcome page: open a sample CRD, see a problem and fix it, pick the Kubernetes version, choose the colours. Each step is one action. cel-lens opens nothing by itself on install or update."

The extension has no walkthrough. The engine checks files on disk only (`documentSelector` `{scheme: 'file', language: 'yaml'}`), in a workspace folder or not, and offers *Change to `replicas`* as the preferred quick fix on `self.replica` in the pictures' `test/pictures/widget_crd.yaml`. On activation the extension opens nothing.

## Goal

The Welcome page offers *Get started with cel-lens*, four steps of one action each, with pictures that read in every theme; *cel-lens: Get Started* opens it; nothing opens by itself.

## Acceptance criteria

- [ ] `contributes.walkthroughs` has one walkthrough, `getStarted`, title *Get started with cel-lens*, description *Check the CEL rules of your Kubernetes YAML as you type.*, no `when`, with four steps, each one button whose label starts with a verb and each with `media.svg` and `media.altText`:
  1. `openSample`, *Open a sample CRD*, button *Open the Sample CRD* (`command:cel-lens.openSample`), done on `onCommand:cel-lens.openSample`;
  2. `fixProblem`, *See a problem and fix it*, button *Fix the Problem* (`command:cel-lens.fixSampleProblem`), done on `onContext:cel-lens.sampleFixed`;
  3. `pickVersion`, *Pick the Kubernetes version*, which says the status bar item shows it and its menu has every setting and toggle, button *Pick Kubernetes Version*, done on `onCommand:cel-lens.pickKubernetesVersion`;
  4. `chooseColors`, *Choose the colors*, which names *Toggle Colors*, button *Choose Color Style*, done on `onCommand:cel-lens.chooseColorStyle`.

  `src/manifest.test.ts` holds the ids, titles, buttons, completion events and that every command a step names is contributed.
- [ ] The sample is a constant in `src/sample_crd.ts`: a `CustomResourceDefinition` `widgets.example.com` of `apiextensions.k8s.io/v1` with `name`, `replicas` and `minReplicas` and four rules, one of them `self.replica > 0`. A unit test parses it as YAML and finds the four rules and the one wrong field.
- [ ] `cel-lens.openSample` writes the sample with `vscode.workspace.fs` to `get-started/widgets.yaml` under `context.globalStorageUri` (creating the folder) unless that file is open in an editor, then opens it in a non-preview editor. When `globalStorageUri` is not a `file:` URI, it writes under `os.tmpdir()` instead, through `vscode.Uri.file`. Tests against `test/vscode.ts`: a first run writes and opens; a run with the sample open and edited writes nothing and shows it; a run after it was closed writes a fresh copy; a `vscode-remote:` storage URI falls back.
- [ ] `cel-lens.fixSampleProblem` opens the sample as `openSample` does, waits up to 10 s for an error diagnostic on it, puts the cursor at the start of the first one and runs `editor.action.quickFix`. With no error by then, it says why once (the engine is not running, with *Show Logs* and *Restart Engine*; or the sample has no problem left, *Open the Sample CRD* writes a fresh one). Tests for each.
- [ ] The context key `cel-lens.sampleFixed` becomes true when the open sample, having had an error, has none (`languages.onDidChangeDiagnostics` for its URI), and false when `openSample` writes a fresh copy. Tests.
- [ ] `cel-lens.getStarted` (*Get Started*) runs `workbench.action.openWalkthrough` with `cel-lens.cel-lens-vscode#getStarted`; in the palette on any file (`when: true`). `cel-lens.openSample` and `cel-lens.fixSampleProblem` are hidden from the palette. `TITLE_VERBS` gains *Get*, *Open* and *Fix*.
- [ ] Each step's picture, `images/walkthrough/<step>.svg`, draws what the step's action opens (the line above a rule, the squiggle and the quick fix list, the version picker, the colour picker) with colours only from VS Code's theme variables (`var(--vscode-…)`), outlines in `var(--vscode-contrastBorder, transparent)`, `currentColor` or `none`. `src/walkthrough_svg.test.ts` parses each, fails on any literal colour (hex, `rgb(`, `hsl(`, a named colour) in an attribute or a `style`, and checks it has a `<title>` and is under 20 KB. `.vscodeignore` ships `images/walkthrough/*.svg`, and the test of the packaged file list holds them.
- [ ] Activation opens nothing: a test against `test/vscode.ts` activates with empty `globalState` and `workspaceState` and sees no `openWalkthrough`, `showTextDocument`, `openTextDocument`, `openExternal` or notification; `package.json` gains no activation event.
- [ ] An e2e case (`test/e2e/engine.test.ts`) opens the sample from `src/sample_crd.ts` as a file outside any workspace folder with the pinned engine (v0.33.0): one error, on `replica`; the code actions there include *Change to `replicas`*, preferred; after its edit, no error.
- [ ] `CHANGELOG.md` has the entry under *Unreleased*; the README's *Get started* section is step 7's.

## Out of scope

The README (step 7); looking at the walkthrough in four themes (step 6 takes it among its pictures). Opening the walkthrough on install: VS Code's own setting `workbench.welcomePage.walkthroughs.openOnInstall` decides that, and cel-lens neither forces nor fights it (the plan's decision 8).

## Notes

- Never write into the person's workspace; the sample lives in the extension's own storage.
- The SVGs are schematic, not screenshots: shapes and the words a person will see (`self: Widget.spec · compiles`, *Change to `replicas`*, `1.36`, *CEL / Classic / Off*), in the theme's own colours, so one file reads in light, dark and both high-contrast themes.
