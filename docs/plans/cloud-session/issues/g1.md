## Context

First step of `docs/plans/cel-lens-everything-one-step-away.md` (JairJosafath/cel-lens#3). The request: "Each thing cel-lens draws in my editor (the colours, and each kind of inline result as they arrive) has a **Toggle** command and a setting, and the toggle is also in the status bar menu. A toggle takes effect at once, without a reload."

Two of the four things drawn already have one: the line above each rule (`cel-lens.inlineInfo`, *Toggle Inline Info*) and its example part (`cel-lens.exampleResults`, *Toggle Example Results*), both through `toggleBooleanSetting` in `src/toggle_setting.ts`. The colours have a setting (`cel-lens.colorStyle`, with `off`) and a picker, but no toggle. The line's value parts (`params: dyn · Give it a type`, `…: {maxReplicas} · Edit`, `Remove`, `variables.limit: int`, `+N more`), which the engine sends only while `cellens-types` is on, have neither. The engine's `inline.Line` sends a line's parts in this order: the rule's state, the value parts, then the example part.

## Goal

*Toggle Colors* turns the colours off and back to the style they had; *Toggle Value Types* hides the value parts of the line while the types keep applying. Both take effect at once and are in the palette where they apply.

## Acceptance criteria

- [ ] `package.json` contributes `cel-lens.toggleColors` (*Toggle Colors*) and `cel-lens.toggleValueTypes` (*Toggle Value Types*), category `cel-lens`. In the palette, *Toggle Colors* has `editorLangId == yaml`; *Toggle Value Types* has `editorLangId == yaml && cel-lens.cellensTypes`. `src/manifest.test.ts` covers both entries.
- [ ] *Toggle Colors* writes `off` to `cel-lens.colorStyle` when the style in force for the active file is not `off`, and when it is `off` writes the style this command last turned off, kept in `globalState`, else `cel`. It writes the scope that sets the value in force (folder, workspace, user), else the user settings, as `toggleBooleanSetting` does, and a failed write is logged and shown once with *Open Settings*. Unit tests: on to off and back to `classic`; back to `cel` with nothing kept; a folder value is written at the folder; a value set only by the legacy `celLens.colorStyle` is read and the new key written; a write that throws.
- [ ] `ColorPainter` repaints at once after the toggle (it follows `cel-lens.colorStyle`): a test against `test/vscode.ts` that fires the configuration change and sees the decorations cleared, then back.
- [ ] `cel-lens.valueTypes`: boolean, default `true`, resource scope, a distinct `order`, a `markdownDescription` that says what it hides (the values a rule reads, with *Give it a type*, *Edit*, *Remove* and `+N more`), that the types still apply, that it needs the experimental feature `cellens-types`, and how to flip it (**cel-lens: Toggle Value Types** or the status bar menu).
- [ ] With `cel-lens.valueTypes` off for a file, the CodeLens middleware keeps, of each line (lenses sharing a start line), its first lens and any lens running `cel-lens.showExampleResults`, and drops the others; on, it changes nothing. It composes with `withoutExampleResults`. Unit tests in a module without `vscode`: a line with a state, two values and `+N more`; a line with an inferred value whose part runs `cel-lens.showRule`; a line with an example part; two lines in one answer; an empty or `null` answer.
- [ ] *Toggle Value Types* flips `cel-lens.valueTypes` with `toggleBooleanSetting`, and the configuration listener in `extension.ts` treats `cel-lens.valueTypes` as it treats `inlineInfo` (`sendLineSettings`, so VS Code asks for the lines again): a test that the change fires the CodeLens refresh, without telling the engine anything new.
- [ ] The extension sets the context key `cel-lens.cellensTypes` to whether `cellens-types` is in `cel-lens.experimental`, at activation and on each change of the setting. A test for each.
- [ ] An e2e case (`test/e2e/engine.test.ts`) with `cellens-types` on asks the pinned engine (v0.33.0) for the lines of a policy whose rule reads a `dyn` `params` and a CRD rule with examples, runs them through the middleware with `valueTypes` off, and gets each line's state part and example part and no value part; on, it gets them all.
- [ ] `CHANGELOG.md` has the entry under *Unreleased*; the README is step 7's.

## Out of scope

The status bar menu's entries for these toggles (step 2), the editor's submenu (step 3), the README (step 7). Toggles for problems, hover or completion: decision 1 of the plan says why there are none.

## Notes

- No engine change: the types still type the rule, its hover and completion; only the parts are hidden. The example part keeps the words the engine fitted to the whole line, which may be its short form; that is accepted (decision 3).
- One word per idea: the setting is `valueTypes`, the menu entry *Value types*, as the commands say *Give a Value a Type…*.
