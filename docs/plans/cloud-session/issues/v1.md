## Context

The engine shows a line above each CEL rule, and for a `dyn` value it offers `Give it a type`, `Edit` and `Remove` (GitHub request JairJosafath/cel-lens#6, the owner's first priority). Those run commands in the extension. The engine owns `.cellens` and offers `cel-lens.typeChoices`, `cel-lens.checkType`, `cel-lens.setType` and `cel-lens.removeType`; the extension asks the person what they mean, as GitLens's quick picks do. `docs/style/vscode.md`, *The UX bar*, is the standard.

## Goal

Clicking `Give it a type` opens a quick pick that lets a person pick a kind or write a struct, with errors as they type; `Edit` and `Remove` do what they say. The extension ships the engine release that has these commands.

## Acceptance criteria

- [ ] `cel-lens.giveType` (from the line's arguments) opens a quick pick titled `Give self.spec.config a type`, with `Write a struct…` first, then the built-in kinds and the workspace CRDs from `cel-lens.typeChoices`, each with an icon telling the two apart and its group and version as the description.
- [ ] `Write a struct…` opens an input box with the placeholder `{name: string, replicas: int}` whose validation message comes from `cel-lens.checkType` as the person types; Enter on a valid type calls `cel-lens.setType`, Escape changes nothing.
- [ ] `cel-lens.editType` opens the same input box filled with the current type; `cel-lens.removeType` removes the entry at once, undoable with Undo in the `.cellens` editor.
- [ ] The palette has `cel-lens: Give a Value a Type…`, shown only in YAML, which lists the current document's `dyn` values and continues as above.
- [ ] `core-version.json` pins the engine release with these commands; `make check` and the README and CHANGELOG say what is new.
- [ ] Tests run against `test/vscode.ts` with the engine's answers faked; no test starts VS Code.
