## Context

Sixth step of `docs/plans/cel-lens-rule-view.md` (JairJosafath/cel-lens#2). The view lists every rule with its state and stays current. The request also asks to filter to rules with problems, a badge that counts them, and a view that follows the editor, highlighting the rule the cursor is in. The engine sets `problem` on each rule and gives each rule's `span` (its list item) and each document's `range`.

## Goal

A person can show only the rules with problems, sees their number on the view's badge even while the view is closed, and, while the view is open, sees the rule they are editing selected in it.

## Acceptance criteria

- [ ] *Show Problems Only* and *Show All Rules* (`cel-lens.rules.showProblemsOnly`, `cel-lens.rules.showAll`, one icon in the view's title bar at a time, by a context key) switch the tree to the rules with `problem`, with their documents and folders, and back. The choice is kept per workspace in `workspaceState` and read at start. With the filter on and no problem, the welcome view says *No rule has a problem* with a *Show All Rules* link.
- [ ] The view's `badge` is the number of rules with `problem`, whatever the filter, with the tooltip `1 rule with a problem` or `3 rules with problems`, and none at 0; it follows each answer, and counts what is known while a scan runs. A test for each.
- [ ] Following the editor: the setting `cel-lens.ruleView.followEditor` (boolean, default `true`, window scope, in the README's settings table and applied live) and *Follow Editor* / *Stop Following* in the view's title menu, which flip it. While it is on and the view is visible, 100 ms after the cursor last moved or the active editor changed, the view selects the rule whose `span` holds the cursor in that file, else the document whose `range` holds it, else changes nothing; it reveals the row (`reveal` with `select: true, focus: false`, expanding its document), never takes the focus, never opens the view, and never selects a row the filter hides (the document instead, when shown). Lookup tests in a module without `vscode`: the cursor on the rule's key, inside a block scalar, between two rules, in a file of several documents, after an edit not yet in the list.
- [ ] `getParent` is implemented, so a rule is revealed under its document and folder.
- [ ] Clicking a rule, which moves the cursor to it, does not make the view jump elsewhere.
- [ ] `src/rule_list.bench.ts` adds: finding the rule at the cursor in a file of 500 rules within a list of 5,000, median within 1 ms; the badge and the filtered tree after a one-file answer, median within 5 ms.
- [ ] `CHANGELOG.md` has the entry; the README is the last step's.
