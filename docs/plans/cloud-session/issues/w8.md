## Context

Last step of `docs/plans/cel-lens-rule-view.md` (JairJosafath/cel-lens#2). Engine v0.32.0 is released with `cel-lens.ruleList`. The extension's view, filter, badge and following are on `main` under *Unreleased*, tested against an engine built from source. The request ends: "The README shows it with a picture."

## Goal

The extension pins engine v0.32.0, the README shows and describes the view with a picture, and v0.40.0 is released.

## Acceptance criteria

- [ ] `core-version.json` pins `v0.32.0` with the SHA-256 of each asset, compared with the release's verified `checksums.txt`; `make check` passes with `CEL_LENS_ENGINE_DIR` at `core-v0.32.0`.
- [ ] An e2e case (`test/e2e/engine.test.ts`) asks the pinned engine for the list on a fixture of two folders, a CRD with a rule that does not compile and one whose example is wrong, a ValidatingAdmissionPolicy and a MutatingAdmissionPolicy, and reads it with the extension's own model: the documents, labels, states and `problem` it expects; then edits a file and gets it back through `since`.
- [ ] `test/pictures/take.ts` takes `images/rule-view.png`: the view open beside a CRD, with a rule with a problem selected by following the editor, the badge showing, in the README's viewport. Its fixtures are in `test/pictures/`. The picture is taken with `npm run pictures`, as #1's were.
- [ ] The README gains a *Rule view* section after *Example results*, with the picture and its alt text, saying what is listed (the kinds, and Kyverno only with `kyverno` on), the label, the states and their words, the click and the context menu, the filter, the badge, following the editor, several folders, the empty states and the limits; *What it looks like* links to it. The commands table gains the view's commands, the settings table `cel-lens.ruleView.followEditor`. *Not supported yet* says that a `v1beta1` CRD and Kyverno's other kinds are not listed.
- [ ] `package.json` and `package-lock.json` are at 0.40.0, and `CHANGELOG.md`'s *Unreleased* becomes `## [0.40.0] - <date>`, with *Changed*: the extension ships `cel-lens-core` v0.32.0.
- [ ] After the merge to GitHub `main`, `release.yml` for the extension at `0.40.0` publishes `vscode-v0.40.0`; the session checks the Linux `.vsix`'s signature and provenance with cosign and that its engine is v0.32.0 with the pinned hash, then closes JairJosafath/cel-lens#2 with a comment going through its list.
