## Context

Fourth step of `docs/plans/cel-lens-everything-one-step-away.md` (JairJosafath/cel-lens#3). The request: "A keyboard shortcut for the toggles I'd use often, that doesn't take one VS Code or a common extension already uses, listed in the README."

The plan's decision 7 picks one: `Ctrl+K L` (`Cmd+K L` on macOS) for *Toggle Inline Info*, while typing in YAML. It was checked on 14 November against VS Code 1.146.0's default keybindings for Linux, Windows and macOS and the `contributes.keybindings` of GitLens 19.6.0 (both keymaps), Red Hat YAML, Kubernetes Tools, Prettier, ESLint, GitHub Copilot Chat, Vim, Docker, Python, Jupyter, Go, Error Lens, Git Graph, Todo Tree and Helm Intellisense: no exact match and no chord-prefix clash in an editor. The extension contributes no keybinding today.

## Goal

`Ctrl+K L` turns the line above each rule off and on in a YAML editor, and a test fails if a contributed shortcut ever takes one VS Code or a listed extension uses.

## Acceptance criteria

- [ ] `package.json` contributes one keybinding: `{"command": "cel-lens.toggleInlineInfo", "key": "ctrl+k l", "mac": "cmd+k l", "when": "editorTextFocus && editorLangId == yaml"}`. `src/manifest.test.ts` holds it, and that every keybinding's command is contributed and in the palette with a `when` its own `when` implies.
- [ ] `src/taken_keys.ts` (`npm run keys`, not in `make check`: it needs the network) fetches VS Code's default keybindings for the three platforms from github.com/codebling/vs-code-default-keybindings and the `package.json` of each extension the plan names, from its repository, and writes `src/taken_keys.json`: per source, its name and version, and its keys normalised (lower case, modifiers in one order, chords split), for Windows/Linux and macOS. The file is committed with the run's output in the pull request.
- [ ] `src/keybindings.test.ts` reads `package.json` and `src/taken_keys.json` and fails, naming the source, the key and its command, on a contributed key (per platform, `mac` or `key`) that equals a taken one, or whose first chord part is a taken single key, or that is a single key starting a taken chord. Bindings whose `when` is `false`, or that apply only with `terminalFocus` or a `focusedView`, never clash with an editor binding and are skipped, with the rule in a comment. It has a case that a key VS Code uses (`ctrl+k ctrl+l`, *Toggle Fold*) fails, and the case `#3` in its name.
- [ ] A test against `test/vscode.ts` that the command the binding runs is the one *Toggle Inline Info* runs (no second handler).
- [ ] `CHANGELOG.md` has the entry under *Unreleased*, with the key for each platform; the README's *Shortcut* column is step 7's.

## Out of scope

Shortcuts for the other toggles: the plan's decision 7 keeps one, for the annotation a person flips while working. The README (step 7).

## Notes

- Vim takes `Ctrl+K` in the editor while `vim.use<C-k>`, as it does for every `Ctrl+K` chord of VS Code's own; the README says how to give it back (`vim.handleKeys`). Do not work around it.
- `Alt+…` and `Ctrl+Alt+…` were rejected because they type characters on some layouts (Option on macOS, AltGr on Windows) or lock the screen on some Linux desktops; do not swap to one.
