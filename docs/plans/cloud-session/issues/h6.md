## Context

Sixth step of `docs/plans/cel-lens-rule-hovers.md` (JairJosafath/cel-lens#4). The request: "a link to the Kubernetes docs for that kind of rule, and to the CEL function's docs when I hover a function."

Today a function's hover links to the cel-spec language definition on its `master` branch, to `https://kubernetes.io/docs/reference/using-api/cel/` (the current release, whatever version is picked; most Kubernetes functions without a heading), or to cel-go's optional values on pkg.go.dev without a version; a Kyverno function gets no link. No hover links to the page for the kind of rule. The plan's decision 8 lists the pages, pinned, all fetched on 14 November.

## Goal

The hover's **Docs:** paragraph links the pinned page for the kind of rule, for the Kubernetes version picked, and, on a function, the pinned page and heading that document it; a release check proves each link answers.

## Acceptance criteria

- [ ] **Docs:** links the page and heading of the plan's table for the field hovered: a CRD `rule` (`#validation-rules`, `#transition-rules` when it reads `oldSelf`), a CRD `messageExpression` (`#the-messageexpression-field`), a ValidatingAdmissionPolicy's five fields, a MutatingAdmissionPolicy's mutation (`#patch-type-apply-configuration`, `#patch-type-json-patch`) and its page for its match conditions and variables, a Kyverno ValidatingPolicy's page (its `messageExpression` and audit annotation headings where they apply). Each link's text names its subject, then *(Kubernetes 1.36)* or *(Kyverno 1.19)*. A table test per field.
- [ ] With **Cost:** near or over, **Docs:** adds `#resource-use-by-validation-functions` on the CRD page; for a policy, `#runtime-cost-budget` on the Kubernetes CEL page.
- [ ] The Kubernetes host is the version picked's: `https://kubernetes.io` for 1.37, `https://v1-36.docs.kubernetes.io` and so on for 1.36 down to 1.33. A test fails for a version of `kubeversion.Supported()` without a host.
- [ ] Every function and macro the environments declare (Kubernetes's at each supported version, and Kyverno's) has its link: cel-spec at `v0.25.2` and its heading where it has one; cel-go's extensions at `https://pkg.go.dev/github.com/google/cel-go@v0.30.0/ext#hdr-<Name>-<Library>` and its optional values at `…/cel-go@v0.30.0/cel#hdr-<Name>-OptionalTypes`; Kubernetes's libraries at their heading on the Kubernetes CEL page; Kyverno's at their library's heading on `https://release-1-19-0.kyverno.io/docs/policy-types/cel-libraries/`. A test lists the declarations, as `docs_internal_test.go` does for the examples, and fails on one without a link. `hoverdocs_test.go`'s links are the pinned ones.
- [ ] `CEL_LENS_LINKS_TEST=1 go test -run Links ./internal/assist/` (skipped otherwise) fetches every page of the table once, for each supported version's host, fails on a status of 400 or more and on a heading id missing from its page (a GitHub page's from its raw Markdown's headings), and fails when the newest supported version's `v1-NN.docs.kubernetes.io` answers while the table sends that version to `kubernetes.io`. `docs/project-notes.md`'s release check gains it.
- [ ] `docs/engine.md` lists the pages; `CHANGELOG.md` has the entry.

## Out of scope

Links in other places (the README, the diagnostics), docs for Kyverno's other kinds, a link check in `make check` (it needs the network).
