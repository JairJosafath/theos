## Context

Fifth step of `docs/plans/cel-lens-rule-view.md` (JairJosafath/cel-lens#2). The engine answers every CEL rule of the workspace with `cel-lens.ruleList` (identity, label, location, span, compile and example states, `problem`), keeps it current with `since` and the notification `cel-lens/ruleListChanged` for a client that sends `initializationOptions.ruleList: true`, and reports the scan's progress. The extension has no view yet; `docs/style/vscode.md` sets the bar (*Views and webviews*, *Feel*).

## Goal

A cel-lens view in the side bar, with its own icon, lists the documents with rules of the workspace and their rules, each with its label and state, kept current as files change; clicking a rule opens it. When there is nothing to list it says why.

## Acceptance criteria

- [ ] `package.json` contributes one view container in the activity bar, `cel-lens` (title *cel-lens*, a monochrome SVG icon in `images/` that reads in light, dark and high-contrast themes), with one tree view `cel-lens.rules` (*Rules*). No activation event is added: the view activates the extension.
- [ ] The extension sends `ruleList: true` at `initialize`, asks for the whole list once the engine runs, then on each notification for what changed `since` its generation, and applies each answer file by file in a model module without `vscode` (`src/rule_list.ts` or similar), unit-tested: a series of answers gives the whole list; `full` replaces it; `removed` drops files; an answer the extension does not read is logged once and leaves the list as it was. A restarted engine starts over.
- [ ] The tree: the workspace folders when there are more than one, in the workspace's order, each with the folder's name; under each (or at the top for one folder) the documents, in the engine's order, then *Open files* for open files in no folder; under each document its rules. A document's label is its `name`, its description its kind and file (`CRD · config/crd/bases/widgets.yaml`; `ValidatingAdmissionPolicy`, `MutatingAdmissionPolicy`, `Kyverno ValidatingPolicy` written out), its icon a product icon per kind. Only documents and folders with rules show. Each item's `id` is the engine's, so expansion and selection survive updates.
- [ ] A rule's label is the engine's `label`; its description is the line's words, `compiles` or `N problems`, then ` · ` and the example words when there are any; its icon, worst first: `error` (compile error), `warning` (compile warning, `wrong` or `error` examples), `pass` (examples pass), `check` (compiles), in theme colours. Its tooltip (Markdown, no command links) has the label, where it is (`v1 · spec.ports[] · rule 0`, `validations[0]`), its CEL in a code block, its first problems, its example words, and, for a kind without example results, that they do not cover it. Every item sets `accessibilityInformation` with the state in words.
- [ ] A folder whose `cel-lens.exampleResults` is off shows no example words or example icon for its rules, as its lines show none.
- [ ] Clicking a rule opens its file with the start of its `location` selected, in a preview editor, focused. A document row expands, never opens. The context menu of a rule has *Show Problems* (runs `cel-lens.showRule` with its location) and *Show Example Results* (`cel-lens.showExampleResults`, only for a rule with example words); neither is in the palette.
- [ ] Only the documents an answer changed fire a tree change; the others keep their items.
- [ ] With no row, a welcome view (`viewsWelcome`, a context key the extension sets) says, in one sentence each with links that name where they go: no folder open (*Open Folder*); the engine not running (*Show Logs*, *Restart Engine*); scanning (*Looking for CEL rules in the workspace…*); nothing found (the kinds cel-lens lists, a link to the README's section, and to the `cel-lens.experimental` setting while `kyverno` is off). A test per state.
- [ ] While `scan.state` is `scanning`, the view shows VS Code's progress bar (`window.withProgress`, `location: {viewId: 'cel-lens.rules'}`) and `TreeView.message` says `Scanning: 4,210 YAML files read, 37 with rules`; both end when the scan does. With `filesLeftOut` above 0 the first row is a warning, `1,203 YAML files not read: the scan reads at most 20,000 files of at most 1 MiB`, with the engine's limits from `initialize`, which shows the logs when clicked.
- [ ] Tests against `test/vscode.ts`, extended only with what they need (`window.createTreeView`, `TreeItem`, `ThemeIcon`, `EventEmitter`, `withProgress` with a view location), typed with `satisfies` against the real API and cleared in `reset()`.
- [ ] `src/rule_list.bench.ts` (`npm run bench`): applying a `since` answer of one file to a list of 5,000 rules and building the changed document's items, median within 5 ms, and at most 1.3x per doubling of the list (`bench_budget.ts`).
- [ ] `CHANGELOG.md` has the entry under *Unreleased*; the README is the last step's.
