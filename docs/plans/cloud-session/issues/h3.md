## Context

Third step of `docs/plans/cel-lens-rule-hovers.md` (JairJosafath/cel-lens#4). The request: "its estimated cost against the API server's budget for the Kubernetes version I picked, so I see a rule near the limit before the API server refuses it".

Today `pkg/check` estimates costs only to explain a cost error the API server's validation of a CRD reports (`costs` in `pkg/check/cost.go`, with the API server's compiler `celschema.Compile`, the version's `EnvSet`, the node's cardinality and the `TotalCost` accumulator). Under the budget, nothing says what a rule costs. Policies get no cost because the API server estimates none (`TestPolicyNoCost`).

## Goal

`pkg/check` answers, for every CEL expression of a file, the cost the API server of the version picked would estimate, its budget, and its schema's total, or why there is none (decision 5).

## Acceptance criteria

- [ ] `check.Costs` takes a file's name and text and the options `check.Check` takes, and answers one entry per CEL expression the check checks, in file order, each with the expression's range, its field path and its CRD version (empty for a schema shared by `spec.validation`). An entry is one of:
  - estimated: the expression's cost (a rule's `MaxCost` times its node's cardinality, a `messageExpression`'s own), its budget (`StaticEstimatedCostLimit`), the total of its version's schema (every rule and `messageExpression` of it), that total's budget (`StaticEstimatedCRDCostLimit`), the rules that add the most (`TotalCost.MostExpensive`), and the causes `drivers` names, each with whether a limit would bound it;
  - not compiled: the expression does not compile;
  - schema not compiled: the API server compiles no rule of its version's schema (the line's `not checked: schema error`);
  - policy: a ValidatingAdmissionPolicy's or MutatingAdmissionPolicy's;
  - Kyverno: a Kyverno ValidatingPolicy's, while `kyverno` is on.
- [ ] The estimate is the API server's: the same compiler and environment as the check, under `UnderVersion`, without the `.cellens` types (the API server never sees them). A truth test runs over the CRDs of `pkg/check`'s tests and testdata at every supported version: an entry is over its budget exactly when `validation.ValidateCustomResourceDefinition` reports that expression's cost error, a schema's total is over exactly when it reports the total's, and an over-budget entry's cost is the number the cost diagnostic prints.
- [ ] Table tests: a rule on the root, on a nested object, on list items under two unbounded lists (the cardinality), on a map's values; a `messageExpression` with its own budget; a schema shared by every version and one per version; `MostExpensive` without the rules under 1% of the total's budget, as the API server leaves them out.
- [ ] Policies and Kyverno: every expression is answered with its kind and no number, at every supported version (beside `TestPolicyNoCost`).
- [ ] A cancelled context stops the estimate and `Costs` answers the context's error.
- [ ] `go test -bench Costs ./pkg/check/` on the 1,000-line CRD of the hover bench and on a CRD whose rules read unbounded lists: reported in the pull request.
- [ ] The exported names have doc comments; `CHANGELOG.md` has the entry (the library's API grows).

## Out of scope

The hover's words (the next step), sizing a fix for a rule under its budget (step 5), a cost on the command line.

## Notes

- `collectRules` with every node wanted and the `compiler` cache of `cost.go` already do the work; `warm` shows the call for every rule.
- The API server skips the per-expression limit for a rule unchanged by an update (ratcheting); `Costs` judges as at creation, as the plan says.
