# aws-lambda-ts (Framework)

A serverless HTTP API on AWS in TypeScript: a Lambda function behind an API
Gateway HTTP API, keeping items in DynamoDB through the AWS SDK v3, with its
infrastructure as a CDK app. Nothing deploys: the check synthesizes the
CloudFormation offline.

- **Supports:** `function`
- **Layout:** `src/handler.ts` creates the DynamoDB document client at
  module scope, reads `TABLE_NAME` and passes each `APIGatewayProxyEventV2`
  to `answer` in `src/api.ts`, which routes `PUT` and `GET /items/{id}`,
  validates input and answers with status codes; `src/items.ts` holds the
  rules and imports neither the SDK nor the `aws-lambda` types;
  `src/item_store.ts` wraps DynamoDB behind the `ItemStore` interface. Tests
  next to the code (`*.test.ts`) use a fake store and a fake document client;
  none calls AWS.
- **Infrastructure:** `infra/stacks.ts` exports `defineStacks(app: App):
  Stack[]`, which adds one stack named after the package (the Container):
  `infra/api_stack.ts`, with an on-demand DynamoDB table (KMS-encrypted,
  point-in-time recovery, deletion protection, `RETAIN`), a `NodejsFunction`
  (Node.js 24, arm64, 256 MB, 10 s, JSON logs to its own log group kept one
  month, its own role granted only `GetItem` and `PutItem` on the table and
  writes to its log group), and an HTTP API with IAM authorization on every
  route, a throttled `$default` stage and an access log kept one month. It
  passes CDK Nag's `AwsSolutions` checks with no acknowledgement.
  `infra/api_stack.test.ts` asserts it with `Template.fromStack`.
- **Writes:** `package.json`, `package-lock.json`, `tsconfig.json`,
  `vitest.config.mts`, `cdk.json`, `src/`, `infra/stacks.ts`,
  `infra/api_stack.ts`, `infra/api_stack.test.ts`, `README.md`,
  `CHANGELOG.md`, `.gitignore`
- **Package:** `name` is the Container, version `0.0.1`, private and
  `UNLICENSED`, an ES module, `engines.node` `>=22`. The SDK clients are
  `dependencies`, which esbuild bundles into the function (not the runtime's
  copy); the CDK, CDK Nag, tsx and the Standard's tools are
  `devDependencies`.
- **Build:** `NodejsFunction` bundles `src/handler.ts` with the installed
  esbuild (`forceDockerBundling: false`, minified, with a source map); never
  Docker. `cdk.json`'s `app` runs `infra/main.ts` with tsx, and its context
  holds the feature flags `cdk init` of aws-cdk 2.1145.0 recommends.
- **Tests:** vitest runs `src/**/*.test.ts` and `infra/**/*.test.ts` in
  Node, with a 60-second timeout for the tests that synthesize a stack.
- **Type check:** `tsconfig.json` is `strict` with `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes` and the other strict flags, Node's types and
  `resolveJsonModule`; `noEmit`. It includes `src`, `infra` and
  `vitest.config.mts`.
- **Lockfile:** `package-lock.json` was generated by npm 11 on Node 24; only its
  two `name` fields are templated, so `npm ci` installs exactly the versions
  in `package.json`. `allowScripts` lets esbuild's install script run.
- **Standard:** made for `aws-standard`, which owns `infra/main.ts`,
  `infra/standard.ts` and `infra/standard.test.ts`. Lists its tools in
  `devDependencies` with exact versions: `eslint` 10.11.0, `@eslint/js`
  10.0.1, `typescript-eslint` 8.71.0, `prettier` 3.9.9, `typescript` 6.0.3,
  `vitest` 5.0.3, `esbuild` 0.28.2, `aws-cdk-lib` 2.273.0, `constructs`
  10.8.1, `aws-cdk` 2.1145.0, `cdk-nag` 3.0.2 and `tsx` 4.23.15. TypeScript
  is 6.0.3 because typescript-eslint 8.71 supports `<6.1.0`.
- **Devcontainer:** `.c4factory/devcontainer.json` uses `c4factory/go:1.26`, the
  Go and Node toolchain CI and agents use, with ESLint and Prettier set up.

## How a template works

Everything in this repository is copied into the new Container repository at the
same path, except `.c4factory/`, which is input for the factory. Files ending in
`.tmpl` are rendered with Go `text/template` (missing keys are errors) and lose the
suffix; a `.tmpl` that renders to only whitespace is left out. Other files are copied
byte for byte. Paths are never rendered, only contents.

Data: `.Project`, `.SoftwareSystem`, `.Container`, `.DisplayName`, `.Type`, the chosen
`.Framework`, `.Standard`, `.Compute` and `.Deployment` (empty when none is chosen),
and `.Connectors` (sorted names). Functions: `has`, `snake`, `upper`, `lower`, `dart`,
plus the `text/template` builtins. No TypeScript file is rendered: the CDK app
reads the stack's name and description from `package.json`.

Each path belongs to exactly one layer; `.devcontainer/**` and `.c4factory.yaml`
belong to the operator. Release a change by tagging a new version and bumping it in
`templates/versions.txt` of C4 Factory; a tag is never moved.
