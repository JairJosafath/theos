# react-vite (Framework)

A web app with pages in React and TypeScript, built with Vite: one page, a pure
module with its unit tests, and a static site in `dist/` that needs no server
of its own.

- **Supports:** `static-site`
- **Layout:** `index.html` is the entry Vite builds; `src/main.tsx` mounts the
  app, `src/App.tsx` is the page; logic in `src/*.ts` modules that import
  neither React nor the DOM, tests next to them (`*.test.ts`); `public/` is
  copied as is.
- **Writes:** `package.json`, `package-lock.json`, `tsconfig.json`,
  `vite.config.ts`, `index.html`, `src/`, `public/favicon.svg`, `README.md`,
  `CHANGELOG.md`, `.gitignore`
- **Package:** `name` is the Container, version `0.0.1`, private and
  `UNLICENSED`, an ES module. React and React DOM 19.3 are `dependencies`;
  everything else is a `devDependency`, since the build bundles what the page
  imports.
- **The app's name** is `index.html`'s `<title>` (the display name, HTML
  escaped); `main.tsx` passes `document.title` to the page, so no TypeScript
  file is rendered.
- **Build:** `vite build` (Vite 8, `@vitejs/plugin-react`) writes the site to
  `dist/`, so a Deployment can ship everything in `dist/`. `npm run dev`
  serves it with hot reload.
- **Tests:** vitest, configured in `vite.config.ts`, runs `src/**/*.test.ts`
  and `*.test.tsx` in plain Node; a test that needs the DOM brings its own
  environment.
- **Type check:** `tsconfig.json` is `strict` with `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes` and the other strict flags, the DOM libraries
  and `vite/client` types; `noEmit`, because Vite bundles. It includes
  `vite.config.ts` so typed linting covers it.
- **Lockfile:** `package-lock.json` was generated by npm 11 on Node 24; only its
  two `name` fields are templated, so `npm ci` installs exactly the versions in
  `package.json`. No package has an install script.
- **Standard:** lists ts-standard's tools in `devDependencies` with exact
  versions: `eslint`, `@eslint/js`, `typescript-eslint`, `prettier`,
  `typescript`, `vitest`, and `eslint-plugin-react-hooks`, which ts-standard
  turns on for this Framework. TypeScript is 6.0.3 because typescript-eslint
  8.71 supports `<6.1.0`.
- **Devcontainer:** `.c4factory/devcontainer.json` uses `c4factory/go:1.26`, the
  Go and Node toolchain CI and agents use, with ESLint and Prettier set up.

## How a template works

Everything in this repository is copied into the new Container repository at the
same path, except `.c4factory/`, which is input for the factory. Files ending in
`.tmpl` are rendered with Go `text/template` (missing keys are errors) and lose the
suffix; a `.tmpl` that renders to only whitespace is left out. Other files are copied
byte for byte. Paths are never rendered, only contents.

Data: `.Project`, `.SoftwareSystem`, `.Container`, `.DisplayName`, `.Type`, the chosen
`.Framework`, `.Standard`, `.Compute` and `.Deployment` (empty when none is chosen),
and `.Connectors` (sorted names). Functions: `has`, `snake`, `upper`, `lower`, `dart`,
plus the `text/template` builtins; `index.html.tmpl` escapes the display name
with `html`.

Each path belongs to exactly one layer; `.devcontainer/**` and `.c4factory.yaml`
belong to the operator. Release a change by tagging a new version and bumping it in
`templates/versions.txt` of C4 Factory; a tag is never moved.
