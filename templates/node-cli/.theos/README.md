# node-cli (Framework)

A command-line program in TypeScript for Node: flags parsed with Node's
`util.parseArgs`, a `run` function tests call directly, a pure module with its
unit tests, and one bundled file behind a `bin` entry, packed by `npm pack`.

- **Supports:** `cli`
- **Layout:** `src/main.ts` passes `process.argv` and the streams to `run` in
  `src/cli.ts` and sets `process.exitCode`; `run` parses, writes and returns
  the exit code without touching global state; logic in `src/*.ts` modules,
  tests next to them (`*.test.ts`).
- **Writes:** `package.json`, `package-lock.json`, `tsconfig.json`,
  `esbuild.mjs`, `vitest.config.mts`, `src/`, `README.md`, `CHANGELOG.md`,
  `.gitignore`
- **Package:** `name` is the Container, version `0.0.1`, private and
  licensed as the repository is scaffolded (`UNLICENSED` with no license, #73), an ES module; `bin` maps the Container's name to
  `out/cli.js`, `files` packs only that and `CHANGELOG.md`, `engines.node`
  is `>=22`. No `dependencies`: esbuild bundles what the program imports.
- **Flags:** `-n, --name`, `--version` (prints `<name> <version>` from
  `package.json`) and `-h, --help`; anything else exits 2 with the error on
  stderr.
- **Build:** `esbuild.mjs` bundles `src/main.ts` into `out/cli.js` (ESM, Node
  22, unminified) with a `#!/usr/bin/env node` shebang and a `require` made
  with `createRequire`, so a bundled CommonJS dependency can load Node's
  modules. `prepack` runs it, so `npm pack` always packs a fresh bundle.
  `out/` is the bundle and `dist/` the release, so a Deployment can ship
  everything in `dist/`.
- **Tests:** vitest runs `src/**/*.test.ts` in Node.
- **Type check:** `tsconfig.json` is `strict` with `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes` and the other strict flags, Node's types and
  `resolveJsonModule`; `noEmit`, because esbuild bundles. It includes
  `vitest.config.mts` so typed linting covers it.
- **Lockfile:** `package-lock.json` was generated by npm 11 on Node 24; only its
  two `name` fields and the `bin` key are templated, so `npm ci` installs
  exactly the versions in `package.json`. `allowScripts` lets esbuild's
  install script run.
- **Standard:** lists ts-standard's tools in `devDependencies` with exact
  versions: `eslint`, `@eslint/js`, `typescript-eslint`, `prettier`,
  `typescript`, `vitest` and `esbuild`. TypeScript is 6.0.3 because
  typescript-eslint 8.71 supports `<6.1.0`.
- **Devcontainer:** `.theos/devcontainer.json` uses `theos/go:1.26`, the
  Go and Node toolchain CI and agents use, with ESLint and Prettier set up.

## How a template works

Everything in this repository is copied into the new Container repository at the
same path, except `.theos/`, which is input for the factory. Files ending in
`.tmpl` are rendered with Go `text/template` (missing keys are errors) and lose the
suffix; a `.tmpl` that renders to only whitespace is left out. Other files are copied
byte for byte. Paths are never rendered, only contents.

Data: `.Project`, `.SoftwareSystem`, `.Container`, `.DisplayName`, `.Type`, the chosen
`.Framework`, `.Standard`, `.Compute` and `.Deployment` (empty when none is chosen),
and `.Connectors` (sorted names). Functions: `has`, `snake`, `upper`, `lower`, `dart`,
plus the `text/template` builtins. No TypeScript file is rendered: the program
reads its name and version from `package.json`.

Each path belongs to exactly one layer; `.devcontainer/**` and `.theos.yaml`
belong to the operator. Release a change by tagging a new version and bumping it in
`templates/versions.txt` of theos; a tag is never moved.
