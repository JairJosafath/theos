# vscode-extension (Framework)

A VS Code extension in TypeScript, bundled with esbuild: a thin `activate()`, a
pure module with its unit tests, and a stand-in for the `vscode` module so tests
run in plain Node.

- **Supports:** `extension`
- **Layout:** `src/extension.ts` activates and wires; logic in `src/*.ts`
  modules that don't import `vscode`, tests next to them (`*.test.ts`);
  `test/vscode.ts` stands in for `vscode` in unit tests, typed with `satisfies`
  against the real API.
- **Writes:** `package.json`, `package-lock.json`, `tsconfig.json`,
  `esbuild.mjs`, `vitest.config.mts`, `src/`, `test/vscode.ts`, `.vscodeignore`,
  `README.md`, `CHANGELOG.md`, `.gitignore`
- **Package:** `name` is the Container, `displayName` its display name,
  `publisher` the project, version `0.0.1`, private and licensed as the repository is scaffolded (`UNLICENSED` with no license, #73);
  `engines.vscode` `^1.100.0` with `@types/vscode` 1.100.0. One command,
  `<container>.sayHello`, under the display name's category; activation is
  implicit through it.
- **Build:** `esbuild.mjs` bundles `src/extension.ts` into `out/extension.js`
  (CommonJS, Node 20, `vscode` external); `vscode:prepublish` makes the
  minified build `vsce package` ships. `out/` is the bundle and `dist/` the
  release, so a Deployment can ship everything in `dist/`.
- **Type check:** `tsconfig.json` is `strict` with `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes` and the other strict flags; `noEmit`, because
  esbuild bundles. It includes `vitest.config.mts` so typed linting covers it.
- **Lockfile:** `package-lock.json` was generated by npm 11 in
  `theos/go:1.26`; only its two `name` fields are templated, so `npm ci`
  installs exactly the versions in `package.json`. `allowScripts` lets
  esbuild's install script run and denies @vscode/vsce-sign's, which packaging
  doesn't need.
- **Standard:** lists ts-standard's tools in `devDependencies` with exact
  versions: `eslint`, `@eslint/js`, `typescript-eslint`, `prettier`. TypeScript
  is 6.0.3 because typescript-eslint 8.71 supports `<6.1.0`. Other Standards
  must fit these or bring their own through a later Framework version.
- **Devcontainer:** `.theos/devcontainer.json` uses `theos/go:1.26`, the
  Go and Node toolchain CI and agents use, with ESLint and Prettier set up.

## How a template works

Everything in this repository is copied into the new Container repository at the
same path, except `.theos/`, which is input for the factory. Files ending in
`.tmpl` are rendered with Go `text/template` (missing keys are errors) and lose the
suffix; a `.tmpl` that renders to only whitespace is left out. Other files are copied
byte for byte. Paths are never rendered, only contents.

Data: `.Project`, `.SoftwareSystem`, `.Container`, `.DisplayName`, `.Type`, the chosen
`.Framework`, `.Standard`, `.Compute` and `.Deployment` (empty when none is chosen),
and `.Connectors` (sorted names). Functions: `has`, `snake`, `upper`, `lower`, `dart`,
plus the `text/template` builtins; `package.json.tmpl` quotes the display name
with `printf "%q"`, which is valid JSON for printable text.

Each path belongs to exactly one layer; `.devcontainer/**` and `.theos.yaml`
belong to the operator. Release a change by tagging a new version and bumping it in
`templates/versions.txt` of theos; a tag is never moved.
